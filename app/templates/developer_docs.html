开发者接入文档 v{{ project_version }}

本系统部署于 https://account.snyqt.top，提供两种接入方式：自有 API 接入 与 OpenID Connect（OIDC）。所有权限均需开发者显式申请，并在用户授权页与管理员审核页公开展示； 未经用户同意，本系统不会向任何应用提供邮箱、手机号等隐私信息。

一、接入方式与服务地址

统一服务地址
授权页：https://account.snyqt.top/oauth/authorize
OIDC 令牌：https://account.snyqt.top/oauth/token
OIDC 用户信息：https://account.snyqt.top/api/oauth/oidc/userinfo
OIDC Discovery：https://account.snyqt.top/.well-known/openid-configuration
自有 API 用户信息：https://account.snyqt.top/api/oauth/userinfo
自有 API 验证码：https://account.snyqt.top/api/oauth/send-verification
两种方式的区别
自有 API 接入（native）：开发者使用 app_id / app_secret 与授权码调用本站接口， 可按需申请五项权限中的任意组合；若申请了验证码权限，可由本站代发邮件 / 短信验证码。

OpenID Connect（oidc）：标准 OAuth 2.0 授权码流程，可接入 Gitea、Nextcloud 等标准客户端。 仅用于身份认证，固定提供基本信息、邮箱、手机号三项，不能调用本站验证码发送接口，验证码需由应用自行发送。
重要说明
OIDC 返回的 id_token 为未签名令牌（alg=none），适用于内网或可信环境； 公网生产环境建议在应用侧校验 sub 与 aud，或直接使用 /api/oauth/oidc/userinfo 获取用户信息。

二、权限范围（scope）

权限公开透明：开发者在「开发者应用管理」中选择，用户在授权页中确认，管理员在审核页中可见。

scope 名称 说明 是否必选
userinfo 基本信息 用户名、用户 ID、头像 必选（所有应用）
email 读取邮箱 读取用户绑定的完整邮箱地址 可选（自有 API）
phone 读取手机号 读取用户绑定的完整手机号 可选（自有 API）
email_code 邮件验证码 允许应用通过本站向用户邮箱发送验证码 可选（仅自有 API）
phone_code 手机验证码 允许应用通过本站向用户手机发送验证码 可选（仅自有 API）
权限规则
1. userinfo 始终授予，不可取消。
2. 自有 API 未申请 email / phone 时，接口不会返回邮箱 / 手机号原文。
3. OIDC 模式固定授予 userinfo + email + phone，且禁止调用验证码接口。
4. 用户可在「第三方安全」页面逐项开关权限（no_userinfo / no_email / no_phone / no_email_code / no_phone_code）， 该限制优先于应用申请，运行时二次生效。

三、开发者配置流程

1
创建应用
登录后进入「开发者应用管理」，填写应用名称、描述、负责人与官网，同时选择授权方式（自有 API / OIDC）与申请权限（scope）。授权方式与权限在创建时一次性确定，之后不可修改；如需调整，只能创建新应用。
2
配置回调地址
在回调配置弹窗中填写登录回调地址与验证码回调地址。该弹窗中的授权方式与权限为只读展示，不可更改。 OIDC 模式在创建时即锁定为基本信息 + 邮箱 + 手机号。
3
管理员审核
管理员在「应用管理 / 待审核应用」中可看到应用申请的授权方式与权限，确认后审批通过并生成 app_secret。
4
接入开发
审核通过后使用 app_id / app_secret 接入对应流程。请妥善保管 app_secret，切勿暴露在前端。

四、自有 API 接入（native）

1
发起授权
将用户重定向到授权页，登录并确认权限后，系统会回调你的登录回调地址并携带授权码。
GET https://account.snyqt.top/oauth/authorize?app_id=YOUR_APP_ID&redirect_uri=https://your-app.com/callback&state=STATE
2
接收授权码
授权成功后回调地址会收到 auth_code 与 code（两者相同，兼容标准 OAuth2）。授权码有效期为 5 天。
https://your-app.com/callback?auth_code=AUTH_CODE&code=AUTH_CODE&state=STATE
3
获取用户信息
使用授权码调用用户信息接口，按已申请的 scope 返回对应字段。
POST
/api/oauth/userinfo
获取已授权用户的信息。返回字段受应用 scope 与用户级限制共同控制。
参数类型必填说明
app_idstring是应用 ID
app_secretstring是应用密钥
auth_codestring是授权码
delete_codebool否是否在本次请求后立即失效授权码，默认 false
 
{
  "success": true,
  "user": {
    "user_id": "abc123def456ghi",
    "username": "示例用户",
    "avatar": "https://account.snyqt.top/static/img/default_avatar.svg",
    "email": "user@example.com",     // 仅当应用拥有 email 权限且用户未禁用
    "phone": "13800138000"           // 仅当应用拥有 phone 权限且用户未禁用
  }
}
curl -X POST https://account.snyqt.top/api/oauth/userinfo \
  -H "Content-Type: application/json" \
  -d '{"app_id":"YOUR_APP_ID","app_secret":"YOUR_APP_SECRET","auth_code":"AUTH_CODE"}'
隐私保护
未申请 email / phone 时，响应中不会出现对应字段； 即使用户已绑定邮箱 / 手机号，也必须同时获得应用 scope 与用户许可。
POST
/api/oauth/send-verification
通过本站向已授权用户发送验证码。OIDC 接入方式禁止调用，自有 API 需分别申请 email_code / phone_code。
参数类型必填说明
app_idstring是应用 ID
app_secretstring是应用密钥
auth_codestring是授权码
typestring是email 或 phone
 
{
  "success": true,
  "message": "验证码已发送"
}
curl -X POST https://account.snyqt.top/api/oauth/send-verification \
  -H "Content-Type: application/json" \
  -d '{"app_id":"YOUR_APP_ID","app_secret":"YOUR_APP_SECRET","auth_code":"AUTH_CODE","type":"email"}'
失败场景
· OIDC 应用调用：返回 403「OpenID Connect 接入方式不支持调用本系统验证码接口」。
· 未申请对应验证码权限：返回 403「该应用未申请对应的验证码发送权限」。
· 用户已设置 no_email / no_phone：返回 403，且不会发送。

五、OpenID Connect（OIDC）接入

1
发现配置
标准客户端可直接读取 Discovery 文档，自动获取各端点与支持能力。
GET https://account.snyqt.top/.well-known/openid-configuration
2
发起授权
参数名使用标准 client_id（即应用 ID），与 app_id 等价。
GET https://account.snyqt.top/oauth/authorize?client_id=YOUR_APP_ID&redirect_uri=https://your-app.com/callback&response_type=code&scope=openid%20profile%20email%20phone&state=STATE
3
换取令牌
使用授权码换取 access_token 与 id_token，支持 client_secret_basic 与 client_secret_post。
POST https://account.snyqt.top/oauth/token
4
获取用户信息
携带 Bearer 令牌调用用户信息端点，字段同样受 scope 与用户级限制控制。
GET https://account.snyqt.top/api/oauth/oidc/userinfo
POST
/oauth/token
标准 OAuth 2.0 令牌端点，仅支持 authorization_code。
参数类型必填说明
grant_typestring是固定为 authorization_code
codestring是授权码
client_idstring是应用 ID
client_secretstring是应用密钥（也可放在 Basic 认证头中）
redirect_uristring否与授权时保持一致
 
{
  "access_token": "AUTH_CODE",
  "token_type": "Bearer",
  "expires_in": 432000,
  "scope": "openid profile email phone",
  "id_token": "eyJhbGciOiJub25lIn0.eyJzdWIiOiJ1c2V...}."
}
curl -X POST https://account.snyqt.top/oauth/token \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=authorization_code&code=AUTH_CODE&client_id=YOUR_APP_ID&client_secret=YOUR_APP_SECRET&redirect_uri=https://your-app.com/callback"
GET
/api/oauth/oidc/userinfo
请求头携带 Authorization: Bearer ACCESS_TOKEN，返回 OpenID 标准声明。
声明说明下发条件
sub用户唯一标识始终返回（用户禁用 userinfo 时仅返回 sub）
name用户名userinfo 权限
nickname / preferred_username登录名userinfo 权限
picture头像地址userinfo 权限
email / email_verified邮箱与是否已验证email 权限且未 no_email
phone_number手机号phone 权限且未 no_phone
 
{
  "sub": "abc123def456ghi",
  "name": "示例用户",
  "nickname": "abc123def456ghi",
  "preferred_username": "abc123def456ghi",
  "picture": "https://account.snyqt.top/static/img/default_avatar.svg",
  "email": "user@example.com",
  "email_verified": true,
  "phone_number": "13800138000"
}
curl https://account.snyqt.top/api/oauth/oidc/userinfo \
  -H "Authorization: Bearer YOUR_ACCESS_TOKEN"
Gitea 配置示例
在 Gitea 的「认证源 → OAuth2 / OpenID Connect」中填写：
· OpenID Connect Discovery URL：https://account.snyqt.top/.well-known/openid-configuration
· Client ID：你的应用 ID
· Client Secret：你的 app_secret
· Scopes：openid profile email phone
详细步骤参见项目内 docs/gitea-sso-guide.md。

六、用户隐私与二次限制

即使应用已获授权，用户仍可在「第三方安全」页面设置以下限制，系统会在每次接口调用时实时校验：

限制项效果
no_userinfo自有 API 返回 403；OIDC userinfo 与 id_token 仅保留 sub
no_email不返回邮箱原文
no_phone不返回手机号原文
no_email_code禁止调用本站接口发送邮件验证码
no_phone_code禁止调用本站接口发送手机验证码
用户自助管理
用户在「第三方安全」页面看到的开关即上述限制项的反向表达：开关打开表示允许，关闭表示禁止。 为兼容旧数据，历史记录中的 no_email / no_phone 仍会同时阻止对应验证码的发送。
最小权限原则
请仅申请业务必需权限。用户拒绝或限制权限时，应用应优雅降级，不得强制要求邮箱 / 手机号。

七、错误码

HTTP 状态错误信息说明
400缺少必要参数 / 参数无效检查 app_id、app_secret、auth_code、type 等
401app_secret 验证失败密钥错误或应用未通过审核
401授权码已过期授权码有效期 5 天，请重新授权
403该应用未申请对应的验证码发送权限权限在创建时固定，需创建新应用并申请该权限
403OpenID Connect 接入方式不支持调用本系统验证码接口OIDC 应用请自行发送验证码
403用户已禁止该应用访问个人信息用户开启了 no_userinfo
404应用不存在或未通过审核确认应用状态为已通过
500服务器内部错误请稍后重试或联系技术支持

八、快速开始

1. 创建并配置应用
进入「开发者应用管理」创建应用，选择授权方式与申请权限（创建后不可修改），随后配置回调地址并等待管理员审核。
2. 选择接入方式
自有系统推荐「自有 API 接入」；需要对接 Gitea 等标准客户端时选择「OpenID Connect」。
3. 实现授权流程
跳转授权页 → 接收授权码 → 调用用户信息接口。OIDC 额外执行 /oauth/token 换取令牌。
4. 联调与上线
建议先在测试环境验证 scope 返回、用户限制与错误处理，再切换生产环境。
